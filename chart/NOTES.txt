The netops sensor is a host eBPF DaemonSet. It cannot run under Pod Security
Standard `restricted` (hostNetwork, hostPath bpffs/btf/sysfs, CAP_BPF /
CAP_PERFMON / CAP_NET_ADMIN / CAP_SYS_ADMIN, runAsUser 0).

If you saw:
  would violate PodSecurity "restricted:latest"
the release namespace is warning or enforcing restricted. Label it privileged:

  kubectl label namespace {{ .Release.Namespace }} \
    pod-security.kubernetes.io/enforce=privileged \
    pod-security.kubernetes.io/audit=privileged \
    pod-security.kubernetes.io/warn=privileged \
    --overwrite

Or set podSecurity.manageNamespace=true so this chart owns the Namespace and
applies those labels. Do not co-locate untrusted workloads in that namespace.

is the node IP. There are two discovery paths, and they are MUTUALLY EXCLUSIVE —
with both on, every sample is ingested twice under two different `job` names:

  1. prometheus.io/scrape pod annotations .... {{ if .Values.metrics.scrapeAnnotations }}ON{{ else }}off{{ end }}
     Needs a `kubernetes-pods` style scrape job on the scraping Prometheus.
     Produces job="kubernetes-pods" and NO nodename label.

  2. headless Service + ServiceMonitor ....... {{ if .Values.metrics.serviceMonitor.enabled }}ON{{ else }}off{{ end }}
     Needs prometheus-operator. Produces job="{{ .Values.metrics.serviceMonitor.jobName }}"
     plus a `nodename` label relabeled from the pod's node — which is what the
     per-node dashboards key on.
